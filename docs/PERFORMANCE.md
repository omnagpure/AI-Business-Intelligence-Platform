# Performance

How long each stage takes, measured with `python -m scripts.benchmark` (no Streamlit needed). Run it on your own computer:

```powershell
python -m scripts.benchmark "path\to\DataCoSupplyChainDataset.csv" "path\to\supply_chain_dataset1.csv" --label mine
```

`--label before` / `--label after` store a run in `docs/perf/<label>.json`; this page is rebuilt from all stored runs (only the block
between the BENCH markers is regenerated, text outside it is kept).

**Read these numbers with care.** They come from a single-CPU Linux sandbox without statsmodels, one run per stage. Run-to-run noise is
roughly 10% (some "changes" below, such as PDF render, are noise: no code in that step changed). Your laptop will differ. Because
statsmodels was missing, the ARIMA and Holt-Winters forecast models were skipped, so the Forecast row is faster here than it will be for you.
Only two of the four real files were available for this run (DataCo and supply_chain_dataset1); the manufacturing sample and the inventory
workbook were not timed.

## What changed (Batch 2)
Output was checked against the original code on both real files: profile, quality report, KPIs, data findings, segmentation, anomalies and
every column role, confidence and evidence line are **identical**; driver importances, metrics and warnings are bit-identical.

| Change | Where | Effect |
|---|---|---|
| Relationship search (revenue = quantity x price, profit = revenue - cost) uses float arrays instead of building pandas objects for every column pair | `semantic/column_classifier.py` | Semantic model 0.88 s to 0.12 s on DataCo |
| Column ranking checks the name before parsing values. `lead_days` ranked every `unknown`-role column by parsing it as numbers first, including Customer Email / Password / names (180k rows of regex each), twice per run | `analytics/kpis.py` (`rank(name_filter=)`), `analytics/supply_chain_kpis.py` | KPIs 2.06 s to 0.89 s, part of segmentation's gain |
| Missing values dropped once per column instead of 6 to 7 times in the profiler | `ingestion/profiler.py`, `ingestion/schema_detector.py` | Ingest 6.3 s to 4.8 s |
| Driver permutation importance preprocesses once instead of once per scoring; forest fit and column scoring use up to 4 threads (`BI_WORKERS` overrides; 1 switches it off). Same random draws, same numbers | `analytics/drivers.py`, `core/parallel.py` | Drivers 16.3 s to 12.3 s on one CPU (from the single preprocessing step). Thread gains need several cores and **were not measured** |
| Dashboard, Insights and Reports share one cache entry for unfiltered KPIs; Insights and Reports already shared the other entries | `ui/shared_results.py`, `ui/dashboard_page.py` | Visiting the pages in any order computes the KPIs once (not timed: needs Streamlit) |
| Charts are drawn once in `build_report` and both renderers reuse the images; HTML is built only when ticked | `reporting/assembly.py` | Verified by a test that counts chart draws |

## What could not be sped up
- **Driver analysis (12 s on DataCo, still the largest step).** Fitting 100 trees (about 5 s) and scoring them 65 times is real work. It
  already fits on at most 20,000 rows by design. More cores should help; fewer trees or repeats would change the results, so they were not touched.
- **Ingest (4.8 s).** About 1.8 s is pandas reading 96 MB of CSV; the rest is per-column profiling (value counts, date parsing).
- **Data findings (2 s) and segmentation (3.1 s).** Findings spend about 1 s parsing dates per group check; segmentation is KMeans with
  n_init=10 for every K plus silhouette scores. Neither was changed.
- **Forecast with statsmodels.** Not measurable here. Expect more than the 0.8 s shown.

## Sampling that already existed (nothing was added)
The statement "all analyses use all rows" is not fully true of the existing code: the semantic classifier looks at up to 5,000 values per
column, the relationship search at 2,000 rows, driver fitting at 20,000 rows (importance on 5,000), and Isolation Forest fits on up to
200,000 rows (all rows are still scored). These limits are in the reports as notes where they matter. Batch 2 added no sampling.

## Target
DataCo from a loaded file to a finished PDF: about 26 s here (4.8 ingest + 0.1 roles + 0.9 KPIs + 2.0 findings + 16.5 four analyses + 1.3
report and PDF). That meets "about a minute or less" in this sandbox; it is **not** a measurement of your laptop.
